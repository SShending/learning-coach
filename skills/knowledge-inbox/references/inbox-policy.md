# Knowledge Inbox Policy

Use this reference for capture shape, duplicate checks, and Inbox triage. The
Inbox is a small retrieval layer, not a second learner-state database.

## Worth Capturing

Capture an item when it has a plausible future retrieval question and at least
one of these signals:

- a reusable distinction, rule, or implementation lesson;
- a source or caveat that would prevent a future mistake;
- a compact answer to a question the learner is likely to ask again;
- a useful pointer whose value is the pointer plus why it matters.

Do not capture a routine definition, a transient answer, generic filler, or a
complete conversation summary. If the learner asks whether something is worth
keeping, show a preview first and wait for approval before writing.

## Item Shape

Prefer a body that answers one retrieval question:

```markdown
# Retrieval question or central idea

## Short answer
## Boundary or caveat
## Example
## Sources
```

Use only the sections that improve retrieval. Keep the body compact enough to
scan. Session chronology belongs in Topic sessions; demonstrated capability
belongs in Topic evidence.

## Triage States

| Status | Meaning |
| --- | --- |
| `inbox` | Captured and awaiting a deliberate decision |
| `snoozed` | Kept, but intentionally deferred from active triage |
| `linked` | Connected to an existing Topic without being promoted into its state |
| `promoted` | A verified Topic note now owns the central idea |
| `dismissed` | Excluded from active views; history remains intact |

`linked` does not imply mastery or a Topic-state update. `promoted` requires a
verified target note and should retain the Inbox item as provenance.

## Duplicate And Promotion Test

Before creating a new item, inspect active Inbox entries for the same central
idea. Before promotion, ask:

> Would losing this item make a future question materially harder to answer?

If the answer is no, keep it out of the Inbox or dismiss it. If an existing
Topic note owns the same idea, hand off for refinement rather than creating a
parallel note. If no Topic is appropriate, keep the item in the Inbox; do not
manufacture a Topic.
