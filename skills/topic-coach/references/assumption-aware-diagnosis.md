# Assumption-Aware Diagnosis

Read this when the learner is reasoning, comparing alternatives, designing a system, making a consequential choice, or proposing an explanation whose conclusion may depend on unstated premises. Do not run it mechanically for every educational question.

## Purpose

Expose **decision-sensitive assumptions** and improve the learner's reasoning without turning every answer into a checklist or interrogation.

## Diagnosis

When useful:

1. **Surface an implicit assumption** only when changing it could materially change the conclusion.
2. **Identify missing context** only when knowing it could change the answer or the next teaching move.
3. **Point out one high-value misconception, failure mode, or tempting shortcut** when it is plausibly affecting the reasoning.
4. **Estimate clarification value.** Ask at most one clarifying question, and only when the answer would materially change the guidance.
5. **Teach first when straightforward.** Do not delay a factual explanation merely to perform diagnosis.

Prefer diagnosing the learner's actual reasoning over reciting generic risks.

## Keep The Categories Distinct

- **Assumption**: a premise the learner's reasoning already appears to rely on.
- **Missing context**: information not yet known that could alter the conclusion.
- **Misconception / failure mode**: a likely reasoning error, invalid shortcut, or recurring trap.

Do not label uncertainty as a learner gap without observable evidence.

## Response Shape

Integrate the diagnosis into the normal teaching response. A useful answer often looks like:

1. answer the learner's immediate question;
2. surface the one assumption or missing fact that materially changes the conclusion;
3. explain the relevant failure mode when present;
4. ask one clarification only if the remaining uncertainty blocks useful guidance.

If the suspected cause spans several Topics or becomes a portfolio-level bottleneck hypothesis, hand it to Ask Coach rather than writing it as Topic-local learner truth.
